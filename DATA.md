# Data and full-run artifacts

The default dashboard profile uses compact committed fixtures in `dashboard/data/`.
It does not need the raw dataset or large model artifacts. A second machine can
select the full profile after copying the files below; the original full-run
copies are on a **friend's laptop**. Set `BPM_DATA_ROOT` only if the `data/`
folder is stored somewhere other than the repository root.

The full dashboard builder reads from `data/processed/` and `data/synthetic/`
and model files under `src/models/`. It writes its six dashboard fixtures only
to `dashboard/data_full/`; full-run reports generated by other project scripts
belong under `reports/full_run/`. It never writes to `dashboard/data/`.

`dashboard/build_dashboard_data.py --run full` applies the same saved models to
the reproduced 70/30 split, builds a 200-borrower test sample, and extracts its
24-month sequences with a PyArrow loan-ID filter. It computes the sampled
borrowers' real LSTM attention weights from the existing checkpoint. No model is
trained. The full attention inference requires the dense LSTM array and saved
checkpoint listed above.

The dashboard itself needs none of those large files to open and display the
committed subsample profile. The full profile requires the files above and
creates small parquet/JSON fixtures under `dashboard/data_full/`. Sensitivity
and full-run reference fixtures are copied from `reports/full_run/` when
present; an absent sensitivity analysis is shown as unavailable rather than
fabricated.
